# GIWA Stocks 실행 연결 승인안

상태: **제안만 작성, 적용하지 않음.** 같은 폴더의 `stocks-activation.patch`는 기존 `server/src/app.ts`, `server/src/index.ts`에 대한 검토용 변경안이다. `git apply --check`로 적용 가능성만 검사했다. 실제 두 파일은 기준 버전 그대로이며, 공개망 서명·전송·배포는 실행하지 않았다.

## 적용 시 동작

- 기존 서버에 Stocks 조회·매수·매도 API를 선택적으로 등록한다. 기존 SIWE 로그인 토큰으로 지갑 소유자를 확인하고, 별도 명명된 운영자 목록으로 Stocks 조회 권한을 확인한다.
- Stocks 설정이 없으면 기존 서버 동작을 유지한다. `STOCKS_MODE=DEMO_TESTNET`일 때만 명시된 공개 배포 명세·RPC·외부 서명 서비스 설정을 검사한다. 체인 91342, 확정 블록, 계약 코드·연결 관계·토큰 소수점·서명 서비스 정책이 맞아야 시작한다.
- `STOCKS_AUTODISPATCH=1`까지 명시한 경우에만 최초 1회와 2초 간격으로 작업 처리를 실행한다. 이 처리는 외부 서명 서비스에 **실제 테스트넷 발행·소각/지급 요청을 보낼 수 있다.** 중복 호출은 단일 실행으로 합치고 종료 시 타이머와 전용 DB 연결을 닫는다.
- 최근 60초 내 확정 블록 관찰이 정상이어야 새 주문과 새 실행을 허용한다. 미확정 거래는 원래 작업·거래 식별자로 조회하며, 결과 불명 상태에서 새 거래를 다시 보내지 않는다.
- 자동 실행을 켜지 않으면 신규 거래는 준비되지 않은 상태로 유지된다. 이 변경안에는 배포, DB 마이그레이션 실행, faucet, 임의 민팅 API, 키 보관, 실제 Alpaca 주문이 없다.

## 필요한 설정과 검증

외부 서명 수단, 신규 Stocks 계약 5개의 공개 주소·코드 해시·연결 관계, 별도 테스트 자산, 정확한 관찰 체크포인트가 필요하다. 비밀키·시드·비밀번호는 채팅이나 앱에 입력하지 않는다. API 인증 토큰은 서버 전용 secret 설정으로만 공급한다.

실제 승인 후 변경안을 적용하고 기존 서버 회귀 테스트, 기본 비활성·잘못된 설정·서명 서비스 장애·서버 종료 테스트를 다시 실행한다. 공개 GIWA 배포와 최초 실거래 검증은 실제 사용할 서명 수단이 정해진 뒤 그 주소와 명세를 기준으로 진행한다. 기존 Saving/Funds 배포는 재배포하지 않는다.

## 승인 경계

자동 승인 검토가 이전 앱 연결 시도를 거절했다. 구체적인 외부 서명 런타임 연결과 자동 테스트넷 거래 전송까지 명시적으로 승인되지 않았다는 사유다. 그래서 이 변경안은 파일로만 준비했으며 우회 연결이나 실행 경로를 추가하지 않았다. 사용자의 승인을 받은 뒤에만 적용한다.
