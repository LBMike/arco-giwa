# GIWA Stocks 서버 연결과 테스트넷 실행

2026-09-17 사용자가 연결·자동 처리 개발을 승인했다. 후보 브랜치의 기존 서버에 선택적 Stocks API 연결과 자동 처리 생명주기가 구현되어 있다. 기본 실행은 Stocks 비활성 상태이며, 실제 공개 GIWA 배포나 서명 서비스 설정을 완료했다는 뜻은 아니다.

## 서버 전용 설정

서버 시작·배포 전 점검·연결 설정 생성 도구는 같은 공개 JSON 읽기 규칙을 사용한다. 입력은 최대 64KiB의 정상 UTF-8 일반 파일이어야 한다. 실제 읽기도 상한을 적용하므로 크기 확인 후 파일이 커져도 무제한으로 읽지 않는다. 잘못된 인코딩은 대체 문자로 바꾸지 않고 거절한다. 입력 경로와 해석된 대상 경로 모두에서 대소문자를 구분하지 않고 `.env*`·`.secrets` 구성요소를 차단한다. 일반 공개 파일을 가리키는 심볼릭 링크는 허용하며, 서버와 점검 도구는 기존 상대 경로도 지원한다. 디렉터리·명명된 파이프·끊어진 링크는 거절한다. 파일 오류는 원본 내용이나 경로 없이 `INVALID_STOCKS_PUBLIC_JSON`으로 반환한다. 이 제한은 애플리케이션의 다른 설정 파일에 적용되는 규칙이 아니다.

| 설정 | 의미 |
| --- | --- |
| `STOCKS_MODE` | 생략 또는 `DISABLED`면 Stocks 설정·RPC·서명 서비스·별도 DB 연결을 시작하지 않는다. 활성화 값은 `DEMO_TESTNET`뿐이다. |
| `STOCKS_CONFIG_PATH` | 검증된 배포 명세와 공개 연결 설정을 담은 서버의 JSON 파일 경로. |
| `STOCKS_SIGNER_TOKEN` | 외부 서명 서비스 인증 토큰. 서버 secret 설정으로만 제공하며 공개 JSON·브라우저·로그에 넣지 않는다. 개인키가 아니다. |
| `STOCKS_DATABASE_URL` | 선택적인 Stocks DB 연결. 생략하면 기존 서버의 검증된 DATABASE_URL을 사용한다. |
| `STOCKS_AUTODISPATCH` | 생략/`0`이면 새 주문이 차단되고 worker/observer tick은 실행되지 않는다. `1`은 DEMO_TESTNET과 완전한 설정을 요구한다. 다른 값은 시작 전 거절한다. |

공개 JSON 구조는 `profile: "DEMO_TESTNET"`, `manifest: <검증된 v2 명세>`, `rpcUrl`, `signerUrl`, `contractPolicyVerified: true`, `paused: boolean`, `operators: [{wallet,operatorId,permissions:["stocks:read"]}]`다. 선택적 `operatorControls: true`로 영속 운영자 중지·재개 기능을 활성화할 수 있다. 생략 또는 false면 기존 경로와 동작을 유지한다. RPC·서명 URL은 HTTPS여야 하며 URL의 사용자 정보·query·fragment는 허용하지 않는다. 서명 서비스 URL은 루트 경로여야 한다. 실제 주소나 명세를 추측해 샘플 값으로 활성화하지 않는다.

운영자 디렉터리는 설정 파일 파싱·직접 런타임 구성·세션 생성에서 같은 규칙으로 검증한다. 지갑은 유효한 0이 아닌 EVM 주소이며 소문자로 정규화한 후 중복을 거절한다. `operatorId`는 1~128 UTF-16 코드 단위의 고유한 문자열이다. 앞뒤 공백·제어 문자·짝이 없는 surrogate는 허용하지 않으며, 정상 한글·이모지는 허용한다. ID는 대소문자를 구분하고 자동으로 잘라내거나 변경하지 않는다. 권한은 `stocks:read`, `stocks:control`만 허용하고 같은 권한의 중복을 거절한다. 위반 시 `INVALID_STOCKS_OPERATORS`로 실패하며 직접 런타임 구성에서도 RPC·서명 서비스·DB 호출 전에 차단한다.

기존 최소 권한 구성을 유지하기 위해 런타임은 운영자가 없는 배열, 권한이 없는 운영자, 조회 전용 및 제어 전용 운영자를 허용한다. 제어 권한이 조회 권한을 자동으로 부여하지 않는다. 배포 전 점검은 별도로 최소 한 명의 조회 운영자를 요구하며, [연결 설정 생성 도구](stocks-integration-bundle.md)는 모든 운영자의 조회 권한과 최소 한 명의 제어 권한을 요구한다. 운영자 설정 변경은 서버 재시작 후 반영된다. 세션 생성 시 디렉터리를 복사하고 요청마다 권한 사본을 반환하므로 입력이나 이전 요청의 결과를 변경해 다른 요청의 권한을 바꿀 수 없다.

`paused: true`는 새 주문과 새 거래 실행을 중지한다. 이미 전송된 거래의 결과 조회·확정과 관찰은 자동 실행을 켜 둔 상태에서 계속 진행한다. 반면 자동 실행을 완전히 끄면 조회 worker도 돌지 않는다. 운영 중 일시 중지와 프로세스 비활성화를 구분한다. 운영자 제어 API와 `/admin/stocks`의 중지/재개 UI가 연결되어 있다. 로컬 시험용 실행은 [직접 운영 안내](../stocks-owner-guide.md)를 따른다.

설정은 시작할 때 한 번 읽어 고정한다. `paused`를 바꾸려면 공개 설정 파일을 수정하고 서버를 정상 종료한 뒤 다시 시작해야 한다. 실행 중 파일 변경을 자동 반영하는 기능은 없다.

운영자 제어를 사용할 때는 `20260920000000_stocks_trading_control` 마이그레이션을 포함한 검토된 이력을 먼저 적용한다. 활성화된 서버는 시작할 때 제어 테이블을 읽어 연결을 검증하며, 테이블 생성이나 자동 재개를 수행하지 않는다. 미등록 상태는 `paused: true, version: 0`이다. 조회에는 `stocks:read`, 변경에는 별도로 `stocks:control` 권한을 운영자 디렉터리에 부여한다. 상세 요청과 응답은 [운영자 제어 API](stocks-trading-control-api.md)를 따른다.

동적 재개는 DB에 저장된 운영자 중지만 해제한다. 설정의 `paused: true`, 자동 실행 비활성, 프로세스 종료, 최신 관찰 부재를 해제하지 않는다. 매 신규 허용 판단은 DB를 다시 읽고, 저장소 오류·오래된 응답이면 차단한다. 이미 허용된 거래나 지갑 요청을 취소하는 기능은 아니며, 중지 중에도 원래 전송의 관찰·복구를 계속한다. 운영자 변경 이력은 DB에 영속 보관하며 자동 7일 삭제 대상이 아니다.

## 시작·종료와 복구

서버가 수신을 시작하기 전에 체인 91342, 확정 블록, 체크포인트, 계약 5개의 코드 해시·생성자 연결 관계·소수점, 외부 서명 서비스 정책, DB의 물리적 금고 바인딩을 검증한다. 서버 시작은 마이그레이션이나 배포를 실행하지 않는다. DB에는 검토된 전체 마이그레이션 이력이 먼저 적용되어 있어야 한다.

자동 처리를 명시적으로 켜면 첫 tick 후 2초 간격으로 실행한다. 한 프로세스에서 tick이 겹치지 않으며, 주문/worker의 DB 잠금과 멱등성이 여러 프로세스의 중복을 방어한다. 관찰 결과가 최신 CURRENT가 아니거나 마지막 성공으로부터 60초를 초과하면 새 주문을 중지한다. 데이터가 오래되면 정상 또는 잔액 0으로 간주하지 않는다.

종료가 시작되면 먼저 신규 실행과 주문 허용을 멈추고 타이머를 취소한다. 이미 진행 중인 작업을 기다린 후 Stocks와 기존 Prisma 자원을 닫는다. SIGINT/SIGTERM은 CLI에서만 등록하고, 반복 신호는 같은 종료 작업을 기다린다. 시작 중 설정·인증 resolver·서버 등록·수신·첫 실행의 어느 단계가 실패해도 획득한 자원을 정리한다. 종료 중 첫 tick이 끝나더라도 타이머가 다시 생기지 않는다.

외부 전송 응답이 유실되면 원래 작업 식별자와 원래 거래만 조회한다. 조회가 없다는 이유로 새 거래를 전송하지 않는다. 재시작 후에도 같은 배포 명세·DB·서명 서비스의 영속 작업 이력을 사용해야 한다. 다른 배포 이름으로 같은 물리적 금고를 새 원장에 연결하거나, nonce를 임의로 바꾸어 복구하지 않는다.

### 외부 연결의 응답 제한

RPC와 서명 서비스의 각 HTTP 요청은 헤더 수신·본문 읽기·JSON 해석을 합쳐 10초의 제한을 둔다.
단순한 연결 시간 제한이 아니므로 본문 일부만 보내고 멈춘 응답도 종료한다. 응답의 늦은 도착이나
중단 신호를 무시하는 전송 구현이 이미 실패한 요청을 성공으로 바꾸지 못한다. 이 시간은 개별
HTTP 요청 기준이며, 여러 요청을 사용하는 전체 worker tick의 종료 시간을 뜻하지 않는다.

RPC 본문은 최대4MiB, 서명 응답은 최대64KiB다. 선언된 Content-Length와 별도로 실제 읽은
바이트를 센다. HTTP 압축을 사용해도 압축 해제 후 크기에 상한이 적용된다. UTF-8이 잘못됐거나
JSON 해석에 실패하면 응답을 거절하며, 자동 redirect나 자동 재시도는 하지 않는다. 오류·404·초과·
시간 초과 응답의 읽기를 취소하고 취소 완료가 무한정 지연돼도 호출자를 대기시키지 않는다.

외부 통신 오류에는 고정 오류 코드만 남기며 원문 응답·요청 URL·인증 토큰을 포함하지 않는다.
서명 PUT의 시간 초과·잘린 응답·과대 응답은 **전송되지 않았다는 증거가 아니다**. 기존 worker는
이를 결과 불명 상태로 보관하고 원래 작업 ID를 조회한다. 조회의404도 새 PUT을 허가하지 않는다.
정상 응답의 작업 ID·payload digest·거래 hash 검증은 계속 적용한다.

## 공개 테스트넷으로 넘어가기 위한 입력

필요한 공개 정보는 배포자·운영 서명자·테스트 자산 faucet 운영자의 서로 다른 주소, 배포자 nonce, 선택한 외부 서명 방식이다. 서명 전 계획은 `stocks-giwa-unsigned-deployment.md`의 도구로 생성한다. 계획 자체는 배포 증거가 아니다. 이후 `stocks-giwa-deployment-verification.md`의 읽기 전용 도구에 원래 승인된 계획 digest·원래 5개 거래 hash·현재 백엔드 ABI digest를 전달해 v2 명세를 만든다. 각 거래의 확정된 실제 배포 내용과 코드·생성자 설정을 다시 확인하며, 파일 출력을 배포 성공으로 대신하지 않는다.

현재 새 테스트 자산 계약의 초기 활성화는 cash/stock 공급량 0에서 검증한다. 공개 테스트 자산 발급과 입금은 검증된 관찰기가 시작된 후 진행한다. 기존 Saving/Funds 주소와 배포 명세는 별개로 유지한다. 이 버전은 NVDA·ARCO_TEST_USDC·고정 모의 가격·모의 브로커이며, 실제 주식 체결 또는 실제 USDC/RLUSD로 표시하지 않는다.

운영 순서는 공개 역할 확인 → 고정 nonce의 서명 전 계획 검토 → 원래 5개 배포 거래 확정 → 읽기 전용 검증과 명세 생성 → 검토된 DB 이력 및 외부 서명 서비스 준비 → `paused: true`, 자동 관찰 켠 상태로 시작 → CURRENT 관찰과 잔액 대조 확인 → 통제된 테스트 자산 발급·입금 및 주문 허용이다. 명세의 관찰 시작점은 첫 계약 생성 블록을 포함하므로 초기 이력을 건너뛰지 않는다. 프로세스 시작은 이 배포 단계나 데이터베이스 적용 단계를 자동 수행하지 않는다.

개인키·시드·비밀번호는 채팅, 브라우저 폼, API/DB/worker, 일반 환경변수에 전달하지 않는다. 기존 지갑으로 배포를 승인할 수는 있지만, 서버의 지속적인 자동 거래에는 위 프로토콜을 구현한 별도 서명 서비스가 필요하다. 제공된 서명 수단에 맞춘 연결은 그 공개 정보가 확인된 뒤 수행한다. 이번 구현은 로컬 테스트용 서명 서비스를 공개망 대체 서비스로 자동 선택하지 않는다.
