# Stocks execution API v1

Authenticated read-only GET endpoints:

- `/api/v1/stocks/execution/deployment`: data is ReviewedDeployment `{status:'VERIFIED',evidenceId,manifestDigest,manifest,verifiedAt,validUntil}`.
- `/api/v1/stocks/execution/:side/:orderId`: side is BUY or SELL. Data is ExecutionPolicy `{allowed:true,deploymentDigest,orderId,side,observedAt,validUntil}`.

Responses use exactly the existing PROFILE five fields plus top-level observedAt (ISO string) and data. Timestamps inside data are integer epoch milliseconds. Every success/error is `Cache-Control: no-store`. Authentication precedes input handling. Query strings and bodies are forbidden, including wallet/address override inputs. The caller's trusted session actor and wallet are the only owner identity. Denials use non-2xx status and a fixed error envelope; there is no allowed=false or fabricated VERIFIED response. Existing explicit CORS and optional route registration belong to app integration; absent service registration leaves routes unavailable.

`StocksExecutionService(stocks, deployments)` exports deployment(actor) and policy(actor,side,id). `stocksExecutionPlugin` and `StocksExecutionPluginOptions` accept service and the existing trusted resolveActor callback. Optional third constructor argument supplies wallNow/monotonicNow solely for deterministic clock injection. Root provides the DeploymentEvidencePort implementation and runtime lifecycle.

Deployment performs synchronous actor/activation checks and calls the trusted evidence port without SQL or pause reads. Trading pause does not invalidate verified deployment identity. Evidence must match both the active manifest digest and the digest computed from the provided public manifest; the response whitelists public fields and exactly five contract code hashes, checks the resulting digest again, and retains original evidence dates. Future, expired or longer-than-15-second evidence is denied.

Policy checks activation and current pause/observer health, then reads current order ownership/wallet/deployment, the existing physical vault-to-deployment binding, immutable new-order enrollment and exact order derivation, payable state and DB-clock quote deadline. This permission read occurs before requesting costly deployment evidence. After evidence, the same read is repeated and pause is rechecked. Historical unenrolled orders, missing/other physical deployment bindings and expired/non-payable orders fail closed. Existing pending/terminal submission history is deliberately not a policy denial: inspect/reconcile recovery needs eligibility before reading that journal.

SQL transactions are `READ COMMITTED READ ONLY`; no FOR UPDATE/FOR SHARE, INSERT, audit, claim, enrollment or binding writes are issued. PostgreSQL prohibits row-locking SELECT in READ ONLY. Tests exercise table-lock waits instead; a separate clock_timestamp query after reads prevents transaction-start time from extending an expired order. Each statement/lock wait is capped at 2 seconds, idle transaction at 3 seconds, and each read phase has a 2.5-second outer budget. Late pool acquisition releases its connection; timed-out work schedules no next data query and rolls back/releases on completion. A stalled transport may delay physical connection cleanup, but cannot cause a write or a successful late response. Entire service work has a 15-second response ceiling; existing trusted evidence verification has its own shorter bound.

Policy observedAt is captured before work. validUntil is the minimum of request-start+15 seconds, unchanged deployment proof expiry, and both DB remaining-lifetime samples. Wall and monotonic clocks independently reject expired work; disagreement reduces the remaining response lease rather than restarting it. Pause after proof/query waits is checked before returning. Read-only SELECT/re-query is a snapshot of eligibility, not an execution lock: state can change after the response. The durable submission claim remains the sole authority for one wallet request and rechecks current state. Policy never permits bypassing the journal, automatically signing, or replaying a past wallet attempt.

Typical denial codes include UNAUTHORIZED (401), ORDER_NOT_FOUND (404), SUBMISSION_NOT_ENROLLED/ORDER_NOT_PAYABLE/ORDER_EXPIRED (409), and STOCKS_PAUSED/EXECUTION_UNAVAILABLE/EXECUTION_DATABASE_TIMEOUT/EXECUTION_POLICY_EXPIRED/EXECUTION_DEPLOYMENT_MISMATCH/EXECUTION_PHYSICAL_BINDING_MISMATCH (503). Raw DB/transport exceptions are sanitized. No secret URL, credential, proof transport detail, signing key or private config is returned.

This API adds no UI, ledger settlement, transaction signing/broadcast, receipt promotion, activation change or deployment. Runtime evidence, app auth/CORS and lifecycle wiring are reviewed in the integration candidate separately.
