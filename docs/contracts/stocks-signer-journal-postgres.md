# Stocks signer PostgreSQL journal — inactive local adapter

`server/src/stocks-signer/postgres-journal.ts` implements the `DurableSignerJournal` port for the inactive signer core. Its dedicated, one-time SQL migration is `server/src/stocks-signer/migrations/0001_journal.sql`. Neither API startup nor Prisma applies this migration. Nothing in this slice starts a signer HTTP service, accesses a key, queries a chain, or broadcasts a transaction. It must not be configured as the product's signer endpoint and does not advertise signer capabilities.

The adapter requires a separately provisioned `stocks_signer.account_nonce` row for chain 91342, the manifest signer address, `networkInstance`, checkpoint number and hash, and an **explicit externally verified** decimal starting nonce. The migration seeds no row and discovers no nonce. The constructor's expected starting nonce must match that immutable row. A changed network instance or checkpoint for the same chain and signer is rejected even if a reset chain happens to report the same nonce; a different deployment with the exact same network and checkpoint uses the same physical account lock and nonce sequence. The initial nonce must be verified against the intended chain and custody policy before any future activation. This adapter cannot perform that verification. A legitimate checkpoint rollover needs a separate reviewed chain-continuity and nonce migration procedure; this slice fails closed.

`reserve` locks the physical account row across processes, checks an existing operation ID for exact immutable identity, and inserts the original call and nonce before incrementing `nextNonce` in one transaction. An unresolved row with no transaction hash blocks every new nonce for that account, including calls from other deployments. A repeat of the same operation ID returns its original nonce without a new reservation. `recordHash` changes only a null hash to one value and rejects a conflicting value. The SQL guards prevent changing or deleting the account identity or operation and prevent creating an operation that already claims a completed hash. The database transaction does not sign or submit anything.

The disposable PostgreSQL harness is `node scripts/stocks-signer/test-postgres.mjs`. It finds a complete PostgreSQL server installation through the existing local discovery code; `STOCKS_PG_BIN` can select an explicit complete bin directory. CI runs it as the `signer-journal` Stocks integration scenario. Its tests cover explicit seeding, network and checkpoint mismatch, real-length refund IDs, competition between independent database pools, same-ID replay, uncertain outcomes, hash compare-and-set, and direct SQL mutation attempts. A separate probe verifies that the unknown original and nonce gate survive an actual PostgreSQL stop/start and a new client process. The harness uses local temporary storage and a Unix socket without TCP listening.

Before any capabilities endpoint can be truthful, a separate transport and custody implementation still must prove that it signs only the persisted call at its original nonce, broadcasts at most once, and finds the original transaction after ambiguous outcomes by verifying signer, nonce, target, calldata, and value. `recordHash` currently accepts a hash from that absent trusted transport; this journal does not independently prove on-chain identity. A production deployment also needs restricted DB roles, backup and restore rehearsal for this dedicated schema, verified external nonce seeding, chain-reset policy, and crash tests around actual signing and broadcast. Until those exist, the signer core and this adapter remain disconnected.
