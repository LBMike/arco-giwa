# Stocks external signer boundary — inactive local slice

These modules are an unconnected protocol boundary for the existing `ARCO_STOCKS_SIGNER_V1` client. They do not start a listener, access a key, or configure a public RPC. The inactive HTTP app factory implements `GET /v1/capabilities` and can return `DURABLE_SERIALIZED` and `IMMUTABLE_IDEMPOTENT` only after its injected authorization and readiness checks pass. Nothing in the product boots that app or configures it as `signerUrl`; this is not a public signer service.

`server/src/stocks-runtime/signer-call.ts` now supplies one canonical allowlist to the client and the future service. Only `mintForOperation`, `refundForOperation`, `settleRedemption`, and `returnEscrowForOperation` are accepted, with their matching `mint:`, `refund:`, `redeem:`, and `return:` operation IDs. The call must match the reviewed manifest's chain, deployment, signer, target, exact calldata and zero value. `parseStocksSignerPut` additionally requires the exact v1 request fields, deployment digest, path operation ID and call digest before touching a journal.

`createStocksSignerCore` reserves the immutable original operation **and its decimal `originalNonce`** through an injected journal before invoking an injected one-shot transport. A missing or malformed nonce is rejected before that call. A repeated PUT for the same ID returns its recorded hash, or an unknown result when no hash is proven; it never invokes the transport again. A changed payload under that ID is rejected. Lookup reads only the original ID and passes its persisted nonce and call to the transport's read-only original-transaction lookup. An absent result never authorizes another send. Store and transport exceptions are reduced to fixed errors without raw provider or database details.

The injected ports have requirements that the core alone cannot prove. The separate [inactive PostgreSQL journal](stocks-signer-journal-postgres.md) uses one database transaction to commit the original operation and nonce before transmission, serializes allocation with a physical account lock, preserves immutable records across restarts, and blocks later nonces while an earlier outcome is unresolved. `recordHash` is compare-and-set and never replaces a different hash. Its disposable PostgreSQL tests verify those database behaviors.

`original-transport.ts` now provides an **inactive** one-shot adapter for an injected external custody signer and JSON-RPC connection. Before the sole `eth_sendRawTransaction` call, it binds RPC chain ID and checkpoint hash to the reviewed manifest; recovers the signer from the signed EIP-1559 bytes; checks the reserved nonce, exact target/calldata, zero value, empty access list, and explicit gas/per-gas/total-fee ceilings; and commits the signed bytes' exact hash through the durable signed-intent port. It then compares the RPC result with that hash. The custody port signs bytes only and must not broadcast or retry internally. An exception or missing send acknowledgement leaves the original outcome unknown; the core never resubmits that operation.

`nonce-lookup.ts` offers a read-only original-nonce locator. It uses historical `eth_getTransactionCount` at the deployment checkpoint and a **finalized** block, then binary-searches the first block that consumed the reserved signer nonce. It returns that block's transaction only if the block and account/nonce identities are coherent. `original-transaction.ts` separately verifies the candidate's chain ID, signer, nonce, target, calldata, zero value and hash against the stored operation. The transport additionally requires its hash to equal the pre-broadcast signed-intent hash before the journal records it. Missing finalized evidence returns unknown; inconsistent or unavailable RPC history fails closed. The provider must support finalized blocks and historical account counts.

`http-rpc.ts` is a separate signer-only RPC client. It allows only chain ID, block, account transaction count, and raw signed transaction methods with strict parameters, HTTPS, bounded responses and no retry. The existing product `httpStocksRpc` stays read-only and cannot broadcast. `http-service.ts` is an unstarted Fastify app factory for the external client's v1 capabilities and operation routes. It requires one high-entropy bearer token, checks authorization before its injected readiness gate, limits request bodies, hides internal errors, and sends no CORS or cacheable responses. Neither module selects a URL, key, database, listener, or activation policy. Tests exercise the existing external signer client against this app in memory; no public port is opened.

`readiness.ts` supplies an optional injected gate for that app. It compares a separately reviewed manifest digest and initial nonce with the journal, rechecks chain 91342, the exact checkpoint and finalized signer nonce, and reads the dedicated PostgreSQL account, signed-intent migration and enabled immutability guards without changing them. A pending nonce visible at the selected RPC must not exceed the journal's next nonce; inconsistent chain or nonce observations fail closed. A provider's pending view cannot prove that no hidden or off-provider transaction exists, so the additional injected custody/operator policy must enforce exclusive account control. Unavailable or timed-out checks return false, so authenticated requests receive 503. This probe is a point-in-time condition, not a custody audit or public activation switch. The local HTTP/PostgreSQL/EVM test exercises the gate with a test-only custody callback.

The disposable `scripts/stocks-signer/test-postgres.mjs` harness composes this transport with the PostgreSQL journal and a separately deployed local EVM. It verifies a real mint, a lost broadcast acknowledgement, a fresh database connection and transport recovering the exact finalized transaction without resending, and a PostgreSQL stop/start that retains the signed commitment. The standalone EVM test uses only an in-memory intent store for fast local debugging.

Before exposing an HTTPS endpoint or a capabilities response, validate restricted database custody, externally reviewed initial nonce seeding, selected external signing custody, a selected signer-only RPC endpoint with finalized historical account-count support, and public GIWA deployment evidence. A process crash after intent commit but before broadcast can leave an unresolved nonce permanently; a dropped accepted transaction has the same operational liveness issue. Define an audited recovery procedure before production activation. The existing local Hardhat signer remains test-only. No unknown lookup result permits a resend or a fresh signer nonce while the original is unresolved.
