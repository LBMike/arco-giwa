# Claude UI 후속 작업 — 003F 운영자 중지·재개

상태: 백엔드 계약 준비. UI 구현·Claude 전달은 아직 수행하지 않았다.

Claude는 UI만 담당하고 Codex는 백엔드·통합 검증을 담당한다. 현재 저장소의
`CLAUDE.md`, `docs/contracts/stocks-trading-control-api.md`,
`docs/contracts/stocks-runtime-status-v1.md`를 먼저 읽고, 검증된 operator-control
후보 커밋에서 별도 clone을 만들어 작업한다. 기존 작업 clone이나 main에 덮어쓰지 않는다.

## 구현 범위

기존 Stocks 운영자 화면에 수동 중지 상태, 종합 거래 가능 상태, 최근 변경 이력과
중지·재개 입력을 추가한다. 기존 signed session 및 명시적 API origin을 재사용한다.
서버·DB·컨트랙트·환경 설정 변경, 실제 지갑 전송, 공개 RPC·배포·push는 범위 밖이다.

- 현재 상태는 `GET /api/v1/admin/stocks/trading-control`, 이력은 `/history`에서 읽는다.
  runtime 진단은 프로세스별 최대 5초 관찰값이므로 변경 권한이나 현재 DB 상태로 대신하지 않는다.
- 변경 요청은 정확히 `paused`, `expectedVersion`, `idempotencyKey`, `reason`만 전송한다.
  최초 읽기 전에는 변경할 수 없고, 이유를 검증한 후 현재 상태와 실행하려는 변경을 보여준다.
  권한은 서버가 판정한다. 클라이언트 role, JWT permission, legacy token으로 추정하지 않는다.
- 작업 중 중복 클릭을 막고, 응답 유실은 실패나 성공으로 단정하지 않는다.
  재시도할 때 같은 명령과 같은 key를 유지한다. 409에서는 최신 상태를 다시 읽고 사용자가
  검토한 뒤 새 명령을 시작한다. 버전을 자동으로 바꿔 충돌한 변경을 재전송하지 않는다.
- POST 응답의 `state`를 현재값으로 표시하고 `change`는 해당 요청의 감사 이벤트로 표시한다.
  과거 resume 재시도의 이벤트와 현재 paused 상태가 다를 수 있다.
- 수동 resume 완료를 전체 거래 재개로 표시하지 않는다. configured pause, 자동 실행 중단,
  프로세스 종료, 관찰/제어 저장소 오류 등 남은 runtime 사유를 함께 표시한다.
- 중지는 이미 승인·전송된 거래를 취소하지 않으며 진행 중 거래는 완료될 수 있음을 알린다.
  조회·기존 hash 복구 기능은 유지한다. 변경 이력은 DB 기록이고 7일 자동 삭제 정책은 없다.
- 404는 기능 비활성/미지원, 403은 접근 또는 변경 거절, 503은 결과 확인 불가로 구분한다.
  세션 종료·계정 변경·API 대상 변경 후 늦게 온 응답이 다른 세션에 표시되거나 재전송되지 않게 한다.
  남아 있는 이전 데이터를 보여줄 때 최신값으로 단정하는 문구를 사용하지 않는다.

## 검증과 인수

실제 렌더·클라이언트 요청 검사로 초기 paused/version0, resume 후 다른 차단 사유 유지,
read-only 운영자, 미등록 세션, 중복 클릭, CAS 충돌, 동일 key 재시도, 오래된 이벤트 replay,
응답 유실, 새로고침·계정 변경, 이력 페이지 끝 및 404/403/503을 검증한다.
모든 생산 UI는 기존 디자인 토큰을 사용한다.

저장소 필수 검사를 실행하고 정확한 commit/tree, 변경 파일, 통과·실패·skip, 남은 제약을
보고한다. 목업/DOM 통과를 실제 DB·EVM 통합 성공으로 보고하지 않는다. Codex가 완성된
UI를 실제 로컬 API·DB·체인에 연결해 중지·복구·재개를 독립 검증한 뒤 인수한다.
