# Claude Code 전달용 — GIWA Stocks UI

GIWA 제품의 UI를 구현한다. 사용자가 정한 우선순위는 GIWA 완성 후 XRPL이다. 현재 검증된 Stocks 백엔드 기준은 `d5dfd6d7716e2476a3a59f9283f3deffe3d6962d`이고, API 설명은 `docs/contracts/stocks-giwa-v1.md`, 어드민 기획은 `docs/specs/giwa-stocks-admin-v1.md`다. 먼저 저장소 지침과 이 문서를 읽고, 별도 작업 브랜치·작업 디렉터리에서 진행한다.

## 화면 방향

흰색 테마를 유지한다. 데스크톱 전체 레이아웃은 1512px를 기준으로 넓히되, 사이드바를 포함해 뷰포트에 반응하도록 구성한다. 작은 화면에서 고정 폭 때문에 가로 스크롤이 생기지 않도록 한다. 왼쪽 탐색과 상단 검색의 구조는 Jupiter를 참고하고, 첫 화면의 종합 상품 안내와 주식 표는 Ondo의 정보 구조를 참고한다.

- 왼쪽: Home, Invest 아래 Saving / Funds / Stocks, Manage 아래 Portfolio / Send.
- Home 상단: Saving과 Funds 카드 2개. 아래: Stocks 표. 기존 Savings·Funds 데이터와 테스트 플로우를 유지한다.
- Stocks: 종목·로고·가격·등락·차트·거래 가능 상태를 읽기 쉽게 표시한다. 누락된 로고는 종목 문자로 대체한다. 차트 데이터가 없으면 준비 중 상태를 보여준다.
- Portfolio: Saving / Funds / Stocks를 구분하되, 실제 보유와 처리 중 수량을 중복 합산하지 않는다.
- 어드민: 운영 현황, 주문 목록/상세, 잔액 대사, 감사 이력의 조회 화면부터 구현한다.

## 실제로 연결 가능한 기능

검증된 백엔드는 **NVDA 1종목 / ARCO_TEST_USDC / 고정 모의 가격 120.000000**이다. 실제 USDC·RLUSD와 실시간 시세, Alpaca 체결로 표시하지 않는다. 40종목 확대는 이후 백엔드 작업이다. SEIBro 상위 40종목 표시는 기준 날짜·매수/매도/보관 등의 순위 기준이 검증된 공개 스냅샷으로 준비하고, 주문 가능 여부는 반드시 서버의 capability를 따른다. 이름만 표시된 종목의 구매 버튼을 활성화하지 않는다.

2026-09-17 승인 후 기존 앱에 선택적 Stocks 등록이 구현되었다. 서버의 완전한 설정과 명시적 자동 실행 옵션이 있어야 거래할 수 있으며 기본값은 비활성이다. 공개 테스트넷 설정이 준비되지 않았으면 명시적인 준비 중/연결 불가 상태를 제공한다. UI 작업에서 서버 설정·서명 서비스·worker를 임의로 활성화하지 않는다. 상태를 성공으로 위장하는 기본 mock fallback도 추가하지 않는다. UI용 독립 fixture는 개발 모드에서만 명확하게 표시한다.

매수는 `/api/v1/stocks/quotes` → `/orders`, 매도는 `/sell-quotes` → `/sell-orders`를 사용한다. 견적에는 사람이 읽는 십진 문자열 수량을 보내고, 응답 금액·수량은 정수 문자열과 명시된 소수점으로 처리한다. 브라우저 부동소수점 계산으로 주문 금액을 다시 만들지 않는다. 요청의 정확한 필드, DTO 및 상태 이름은 검토된 API 문서를 따른다.

입금과 에스크로는 주문 생성 후, 검증된 배포 명세의 정확한 토큰·주소·금액으로 사용자의 지갑이 서명한다. 서버 개인키를 받는 UI는 없다. 지갑 서명 성공이나 트랜잭션 해시 수신만으로 주문 완료를 표시하지 않고 서버가 반환한 확정 상태를 기다린다. 현재 EVM 서명 로그인 범위를 활용하되 소셜 지갑 생성과 Xaman 연결의 성공 동작을 새로 만들어내지 않는다. 이 두 기능은 별도 백엔드 연동 작업이다.

## 상태와 검증

입금/에스크로 대기, 처리 중, 완료, 반환, 결과 확인 중, 유동성 대기, 운영 검토 필요를 구분한다. `UNKNOWN`은 실패로 단정하지 않으며 같은 주문을 새로 만들거나 재전송하는 버튼을 제공하지 않는다. 서버 멱등 키는 한 주문 시도 동안 유지한다. 로딩·빈 목록·연결 실패·오래된 관찰 데이터도 각각 표시한다.

포트폴리오의 `walletQuantity`, `escrowedQuantity`, `reservedQuantity`, `availableQuantity`를 구분한다. `quantity`는 경제적 보유 총량이며 예약량을 다시 더하지 않는다. 대사 결과 `MATCHED_AT_CUTOFF`는 해당 확정 블록 기준 일치로 표시하고, `UNAVAILABLE`이나 `INCOMPLETE`를 잔액 0 또는 정상으로 바꾸지 않는다.

운영자 UI는 서버가 확인한 명명된 조회 권한을 사용한다. 현재 관리자 API는 조회 전용이다. 강제 완료·임의 발행·잔액 수정·중지/재개·환불 실행 버튼은 아직 구현된 기능으로 제공하지 않는다.

완료 시 실제 연결한 API, 지원되지 않아 준비 중으로 둔 기능, 데스크톱/모바일 화면, 접근성 및 기존 Saving/Funds 회귀 결과를 함께 제출한다. 변경 파일과 정확한 커밋을 별도 검증 에이전트에게 넘기며, 확인된 P0/P1은 수정 후 재검증한다.
