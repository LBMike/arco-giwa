# Stocks 직접 실행·운영·수정 안내

이 안내의 대상은 **NVDA + 테스트 현금 + 모의 브로커**입니다. 실제 주식이나 실자금 거래가 아닙니다.
운영자·투자자 화면은 제품 코드를 사용하고, 실행 도구가 별도 로컬 DB·체인·테스트 지갑을 연결합니다.

## 처음 준비하기

macOS 또는 Linux, Node22.15 이상, Corepack, PostgreSQL16 이상이 필요합니다.
PostgreSQL은 클라이언트(libpq)만으로는 부족하며 서버 프로그램도 있어야 합니다.
설치 경로는 실행 도구가 자동 확인합니다. 다른 경로라면 `STOCKS_PG_BIN`에 bin 폴더의 절대 경로를 지정하세요.
이미 실행 중인 PostgreSQL 서비스나 사용자 DB는 사용하지 않습니다.

저장소 폴더의 터미널에서:

```sh
npm run stocks:setup
npm run stocks:doctor
npm run stocks:dev
```

`setup`은 잠금 파일 기준 의존성을 설치하고 Prisma 클라이언트·계약·서버를 빌드합니다.
최초 설치에는 인터넷이 필요합니다. `doctor`는 부족한 항목과 해결 명령을 표시하며,
DB 생성이나 거래를 하지 않습니다. `dev`는 서버 코드를 다시 빌드하고 임시 서비스를 시작합니다.
준비가 끝나면 터미널에 **투자자 화면**과 **운영자 화면** 주소가 표시됩니다. 포트는 실행마다 달라집니다.
별도 브라우저 설치 자동화나 개인 지갑 확장 프로그램은 필요하지 않습니다.

실행 도구는 `.env`를 읽지 않고, 상속된 공개 DB·지갑·서명 서비스 설정도 전달하지 않습니다.
기존 `npm run dev`/`start:server`는 원래 서비스용 명령입니다. 이 테스트 환경은 `stocks:dev`를 쓰세요.

## Dynamic으로 본인 지갑을 연결하는 경우

위 `stocks:dev` 화면은 실행 도구가 만든 테스트 지갑을 사용합니다. 이 화면에서
Account A를 고르는 것은 Dynamic이나 본인 지갑 연결을 검증한 것이 아닙니다.

본인 지갑은 일반 제품 앱의 `/stocks`에서 연결합니다. 제품 빌드 환경에 기존
`VITE_DYNAMIC_ENVIRONMENT_ID`가 설정되어 있어야 하며, API·RPC·배포 컨트랙트는
서로 같은 Stocks 테스트넷 배포를 가리켜야 합니다. 공개 환경 ID는 비밀 API 토큰과 다릅니다.
개인 지갑의 공개 GIWA 네트워크를 임시 로컬 체인과 혼용하면 체크포인트 검증에서 차단됩니다.

현재 지원 경로는 **Dynamic에서 선택한 설치형 브라우저 지갑**입니다.
연결된 계정·네트워크가 일치하면 Stocks 로그인 후 주문, 정확한 수량 승인, 별도 입금·예치를
진행할 수 있습니다. 지갑 확인 창의 승인·거절은 사용자가 직접 합니다.
이메일·소셜 내장 지갑과 모바일 WalletConnect의 Stocks 거래는 아직 지원하지 않습니다.
다른 지갑으로 몰래 대체하거나 지갑 전송을 자동으로 재시도하지 않습니다.

이 경로의 코드·모의 제공자 검사는 통과했지만 실제 Dynamic 환경과 개인 지갑 검증은
별도로 필요합니다. 공개 테스트넷 Stocks 배포, 운영자 설정, 테스트 현금과 테스트 가스가
준비되어야 전체 거래를 검증할 수 있습니다. Dynamic 로그인 성공만으로 이 조건들이 갖춰진 것은 아닙니다.

## 운영자로 거래 허용하기

1. 터미널에 표시된 운영자 화면 주소를 브라우저에서 엽니다.
2. 위쪽 로컬 제어 영역에서 **Operator (sign-in only)**를 누릅니다.
3. **Sign in to Stocks**로 로그인합니다. 로컬 테스트 계정이므로 개인 지갑 승인은 없습니다.
4. 거래 제어 영역의 사유를 입력하고 **Review resume → Confirm resume**을 누릅니다.
5. 다시 막으려면 **Review pause → Confirm pause**를 사용합니다. 변경 이력이 DB에 기록됩니다.

처음에는 중지 상태입니다. 운영자의 재개는 체인 관찰 등 다른 조건을 무시하지 않습니다.
로컬 체인은 거래가 없어도 10초마다 빈 블록을 생성합니다. 장시간 화면을 열어둔 뒤
마지막 블록이 오래되었다는 이유로 거래가 막히는 것을 방지합니다. 실행 도구가 만든
로컬 체인에만 적용되며, 운영자의 중지 상태와 실제 서비스의 최신성 검사는 유지됩니다.
중지 후에도 기존 전송의 조회·복구는 가능합니다. 운영자 계정의 지갑 기능은 로그인 서명에 한정됩니다.
Account B는 읽기 전용 운영자, Account A는 투자자입니다.

## 투자자로 매수·매도하기

1. **Account A**를 선택하고 터미널의 투자자 화면 주소로 이동합니다.
2. **Sign in to Stocks**로 로그인합니다. 첫 시작의 테스트 현금은2,000, NVDA 모의 가격은120입니다.
3. Stocks 탭에서 NVDA를 열고 수량을 입력합니다. **Get quote → Place buy order**를 누릅니다.
4. 주문 지갑 패널에서 상태 확인, 승인, 이체를 각각 진행합니다. 승인만으로 매수가 끝나지 않습니다.
5. 완료 후 Portfolio에서 수량을 확인합니다. 매도는 SELL을 선택해 동일한 순서로 진행합니다.

검증된 예: 2주 매수 후0.5주 매도 → 주식1.5, 투자자 현금1,820, 금고180, 에스크로0.
주문이 불확실하면 새 주문·재전송을 반복하지 말고 기존 주문과 알려진 거래 hash의 복구 화면을 사용하세요.

## 위쪽 로컬 제어 도구

| 도구 | 용도 |
| --- | --- |
| Account A / Account B / Operator | 역할 전환. 전환 후 제품 로그인을 다시 해야 합니다. |
| 백엔드 변경 적용 | 서버 코드를 새로 빌드해 반영합니다. 같은 세션의 로그인·DB·체인·주문·중지 기록을 유지합니다. |
| Restart API | API만 재시작합니다. 같은 세션의 DB·체인·주문·중지 기록은 유지합니다. |
| Pause processing / Resume processing | 시험용 worker 처리를 멈추거나 재개합니다. 제품의 운영자 중지와 별개입니다. |
| Hold next response / Release / Drop | 다음 테스트 지갑 응답을 지연·반환·유실시켜 복구를 시험합니다. 거래 자체를 취소하지 않습니다. |
| Next login: 30s JWT | 다음 투자자 로그인 한 번만 짧게 만들어 만료 복구를 시험합니다. |
| Refresh test state | 테스트 계정과 호출 수를 다시 읽습니다. |
| Account A 현금 2,000까지 보충 | Account A의 테스트 현금이 2,000 미만이면 부족분만 발급합니다. 주문·보유 주식·거래 중지 상태를 유지합니다. |
| 테스트 거래 요약 저장 | Account A의 최신 매수·매도 주문 식별번호·상태와 잔액을 JSON 파일로 다운로드합니다. |
| 로컬 실행 종료 | 소유한 로컬 서비스를 종료하고 이번 시험 데이터를 삭제합니다. |

계정 선택은 이 로컬 실행 전체가 공유하므로 처음에는 한 브라우저 탭으로 사용하세요.
제품의 장기 운영용 관리 기능과 상단 시험용 도구를 구분하세요.

현금 보충은 선택한 계정과 관계없이 Account A에만 적용됩니다. 잔액이 이미 2,000 이상이면
추가 발급하지 않습니다. 현금 표시는 최근 조회값이므로 **Refresh test state**로 갱신하세요.
잔액을 읽은 뒤 부족분을 발급하므로 보충 중에는 다른 탭에서 거래하지 않는 것이 확인하기 쉽습니다.
보충은 개인 지갑 승인 없이 이 실행의 로컬 faucet 계약을 이용하며, 공개 테스트넷이나 실제 자산을 사용하지 않습니다.
전송 결과가 불확실하면 같은 실행에서 추가 보충을 차단합니다. 자동으로 다시 보내지 않으며,
API만 재시작해도 차단을 풀지 않습니다. 기존 주문 확인·복구는 계속할 수 있습니다.

## 종료·재실행과 데이터

종료 전에 **테스트 거래 요약 저장**을 누르면 새로 조회한 결과를 컴퓨터에 저장할 수 있습니다.
현재 선택 계정과 관계없이 Account A가 대상이며, 주문은 생성 시각 기준 최신 매수·매도 각각
최대 100건의 식별번호와 상태만 포함합니다. 주문별 수량·체결 가격·전체 거래 이력은 포함하지 않습니다.
현재 테스트 현금·주식·금고·에스크로 잔액은 소수점 문자열과 원래 단위를 함께 보관해 정밀도를 유지합니다.
파일에는 로그인 토큰·로컬 접근 키·지갑 서명·원본 진단 로그를 넣지 않습니다.

이 파일은 나중에 읽어볼 요약이며 DB·체인 복원용 백업이 아닙니다. 조회 중 거래가 진행되면
주문과 체인 잔액의 관측 시점이 다를 수 있습니다. 다운로드한 파일은 로컬 실행 종료 후에도 남고,
저장 버튼 자체는 거래·잔액·중지 상태를 변경하지 않습니다. 별도 서버 재시작 없이 현재 실행에서도 사용할 수 있습니다.

상단의 **로컬 실행 종료**를 누르거나 실행한 터미널에서 **Ctrl+C**를 누릅니다. 소유한 API·화면 서버·DB·체인만 종료하고 임시 데이터를 삭제합니다.
다음 `stocks:dev`는 새 계정 상태와 초기 현금으로 시작합니다. 이것이 전체 시험 초기화 방법입니다.
API 재시작은 기록을 유지하지만, 전체 실행 종료 후에는 테스트 거래 기록을 보존하지 않습니다.
작성한 소스 코드는 저장소에 남습니다. 시작 실패 시 진단 폴더가 남을 수 있으며 경로가 출력됩니다.

운영자 변경 이력에 자동7일 삭제 기능을 추가한 것이 아닙니다. 위 삭제는 이 임시 시험 환경의 전체 종료 동작입니다.
실제 서비스 DB의 백업·보존과는 별개입니다.

UI 파일 수정은 개발 서버가 반영합니다. 변경이 보이지 않으면 브라우저를 새로고침하세요.
`server/src`의 백엔드 코드 수정은 상단 **백엔드 변경 적용**을 누르세요. 전체 서버를 별도 디렉터리에
빌드한 뒤 API와 거래 처리기를 교체합니다. 주소, 로그인, 주문, 잔액, 운영자 중지 상태를 유지하며
성공하면 상단 백엔드 버전 숫자가 증가합니다. 빌드 오류가 나면 기존 서버를 유지하므로 실행 터미널의
오류를 수정하고 다시 적용하세요. 적용 중에는 API가 잠시 연결되지 않을 수 있습니다.

컨트랙트·DB 스키마·로컬 실행 도구 자체를 변경한 경우에는 Ctrl+C 후 `stocks:dev`를 다시 실행해야
합니다. 전체 종료 시 임시 시험 기록이 삭제되므로 필요한 요약을 먼저 저장하세요.
업데이트 전부터 실행 중인 환경에는 이 버튼이 없으며, 새로 시작한 환경부터 지원합니다.
Claude의 제품 UI 담당 범위는 유지하며, Codex는 백엔드·실행 도구·검증을 관리합니다.

모의 가격·지원 종목을 바꾸는 것은 운영 화면의 단순 표시 수정과 다릅니다.
현재 거래 가능 종목은 NVDA 하나입니다. 새 거래 종목·가격 공급자는 계약·견적·원장·검증의
일관성을 함께 구현해야 합니다. 브라우저 표시를 바꿨다고 주문 지원이 생기지 않습니다.
시장정보 영역의 **시세 연결 준비 중**은 정상입니다. 외부 시세 키를 사용하지 않으므로 실제 시장 가격·차트는 표시하지 않으며, 주문의 고정 모의 가격120과 구분합니다.

## 수정 후 확인

별도 시험 DB의 백업·복원도 직접 확인할 수 있습니다.

```sh
npm run stocks:recovery:check
```

현재 사용 중인 거래 기록을 백업하는 명령은 아닙니다. 새 테스트 DB를 만들어 복원 후
주문·거래 증거·운영자 이력 유지와 중복 방지를 확인합니다.
절차와 범위는 [백업·복원 리허설](contracts/stocks-backup-restore-rehearsal.md)에 정리했습니다.

외부 테스트 환경을 준비할 때는 [배포 전 검사](contracts/stocks-preflight-v1.md)를 사용합니다.
이 검사는 DB 테이블·설치 이력과 함께 거래 기록을 보호하는 규칙의 누락·비활성화·변경을 확인합니다.
검사 실패를 자동으로 수리하거나 운영 중인 거래를 중지하는 명령은 아닙니다.

```sh
npm run typecheck
npm run build
npm run test:security
npm run test:server
```

전체 DOM·DB·브라우저 검사는 GitHub의 Stocks integration에서 수행합니다.
`owner-workspace` 항목은 위 실제 실행 명령, 운영자 재개, 매수·매도, API 재시작과 화면에서의 종료를 검증합니다.
기존 디자인 토큰 위반7건은 별도 알려진 항목입니다. 새 위반을 추가하지 마세요.

## 현재 공개 서비스와의 차이

백엔드 실행 이미지는 `npm run stocks:container:build`로 만들 수 있습니다.
[컨테이너 실행 안내](contracts/stocks-backend-container.md)에 빌드·시작·종료와 외부 설정 주입
방법을 정리했습니다. 이미지 생성은 공개 배포나 DB·서명 서비스 생성을 수행하지 않습니다.

외부 배포 명세와 서버 주소를 준비한 후에는 `stocks:integration:prepare`로
중지 상태의 백엔드 설정과 UI 연결 설정을 함께 만들 수 있습니다.
[연결 설정 준비 안내](contracts/stocks-integration-bundle.md)에 입력·실행·적용 순서를 정리했습니다.
파일 생성만으로 서버가 시작되거나 공개 테스트넷 거래가 허용되지는 않습니다.

외부 API를 시작한 뒤에는 [API·UI 연결 점검](contracts/stocks-connection-check.md)으로
서버 응답, Stocks 준비 상태와 브라우저 접근 설정을 확인할 수 있습니다. 검사에 로그인이나
지갑 서명이 필요하지 않으며 주문을 만들지 않습니다.

이 실행은 내 컴퓨터의 루프백 주소에만 열립니다. 공개 배포·실제 지갑·실제 증권 브로커 연결을 뜻하지 않습니다.
공개 테스트 환경에는 호스팅/DB 대상, 명확한 공개 역할 주소, 제한된 외부 서명 서비스와
실제 Stocks 배포 증거가 추가로 필요합니다. 기존 LIVE Savings/Funds 계약은 재배포 대상이 아닙니다.
